# projects ― 実装本体

> **位置づけ:** `docs/ideas/` で「作る」と決めたアイデアの実装を置く。1プロジェクト＝1ディレクトリで、依存関係・テスト・README をその中で完結させる（プロジェクト同士は独立して動かせる・捨てられる状態を保つ）。

## 1プロジェクトの標準構成
```
projects/<プロジェクト名>/        # 英小文字スネークケース
├── README.md          # 冒頭に IDEA-XXXX / SPEC-XXX、何をするか、使い方、必要な環境変数
├── requirements.txt   # このプロジェクトだけの依存（Node なら package.json）
├── main.py            # エントリーポイント（規模が大きくなったらパッケージ化）
└── tests/             # 実通信なしのユニットテスト（CI が自動実行）
```
新規作成は `start-project` スキル（`.claude/skills/start-project/SKILL.md`）の手順に従う。

## ルール
- 秘密情報はリポジトリに置かない。必要な環境変数はルートの `.env.example` に追記する。
- 定期実行が必要なら `.github/workflows/<プロジェクト名>.yml` を足す（cron には日本時間の注記を付ける）。
- 使わなくなったプロジェクトは削除してよい。その場合はアイデアのステータスを更新し、判断ログに理由を書く（コードは git 履歴に残る）。
