# Repository overview

DeFactory株式会社の事業アイデア・開発アイデアを蓄積し、実装まで進めるためのリポジトリ。アイデアと知見を扱う「ドキュメント資産」（`docs/`）と、それを形にする「実装」（`projects/`）の二層で構成される。

## ディレクトリマップ

| パス | 役割 |
| --- | --- |
| `docs/ideas/` | 事業アイデア・開発アイデアの一次受け皿。1アイデア＝1ファイル（`IDEA-XXXX`）。ステータスで「着想 → 検討 → 検証 → 実装 → 運用」の進捗を管理する。 |
| `docs/knowledge/` | アイデアの根拠になる事実（fact）と、そこから導いた気づき（insight）。 |
| `docs/spec/` | 実装すると決めたアイデアの仕様書（実装の正）。 |
| `docs/dev-log/` | AIセッションをまたぐ実装引き継ぎメモ。 |
| `docs/todo/` | 検証・実行タスク。 |
| `projects/` | 実装本体。1プロジェクト＝1ディレクトリで、依存・テストもその中で完結させる。 |
| `config/` | 共通の設定・認証情報テンプレート。実際の秘密情報は `.gitignore` で除外。 |
| `.github/workflows/` | CI（各プロジェクトのテスト）とスケジュール実行。 |
| `.claude/` | Claude Code 自身の設定。詳細は `.claude/README.md`。 |
| ルート `変更履歴.md` | ドキュメント・ディレクトリ構造を変更した際の決定記録（新しい記録を上に追記）。 |

## 関連リポジトリ

- `defactory-tomita/SES_sales` — SES営業の自動化基盤。本リポジトリのフォルダ構成・ルールはここから踏襲している。SES営業に直結する実装はあちら、営業に限らない事業・ツールのアイデアと試作はこちらに置く。SES_sales の `docs/knowledge/insight/` から生まれたアイデアは、`出所` にそのパスを書いて参照する（内容はコピーしない）。

## 最初にすること

新しい情報をどこに書くか迷ったら、まず `docs/README.md` の判断フローに従う。内容の重複を避けるため詳細はここには書かない。
