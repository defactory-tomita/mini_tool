# Docs routing

`docs/` への追記・変更を行う前に、必ず `docs/README.md` の「新しい情報が来たら、どこに書く？」の判断フローを読む。内容はここでは重複させない。

## ルール

- アイデアはいきなり `docs/spec/` や `projects/` に書かず、まず `docs/ideas/` に `IDEA-XXXX` として登録する。実装に進むと決めてから spec・projects を作る（`start-project` スキル）。
- アイデア・知見の一覧表（各 `README.md` の「現行ファイル一覧」）は、ファイルの追加・ステータス変更のたびに更新する。
- `docs/` 配下・`projects/` 直下のディレクトリ構造やファイルの位置づけを変更したときは、背景込みでルート直下の `変更履歴.md` に記録する（新しい記録を上に追記）。アイデア・知見・dev-log・todo の追加だけなら不要。
