# アイデア登録

スキーマとステータスの定義は `docs/ideas/README.md` が正。着手前に読む。

## 新規登録
1. まず既存アイデアを Grep し、同じテーマがあれば新規作成せず追記する（本文に追記し、判断ログに行を足し、`更新日` を今日にする）。
2. `origin/main` 上の `docs/ideas/IDEA-*.md` の最大番号 +1 を ID にする（4桁ゼロ埋め）。手元のブランチだけを見ると他のPRと番号が衝突しやすいため。
3. `docs/ideas/_template.md` をコピーして埋める。
   - ユーザーが話した内容だけを書き、無いことは推測で埋めない。分からない欄は空欄のままにし、「次の一手」に「〇〇を確認する」と書く。
   - `種別` が判断できなければユーザーに聞く。`インパクト`・`手間` は自分の見立てを置き、報告で「暫定」と明記する。
   - `ステータス` は原則 `着想`。課題・仮説まで話されていれば `検討中`。
   - `出所` には会議名・日付、または SES_sales の insight パス（`SES_sales:docs/knowledge/insight/xxx.md`）を書く。
   - 日付は日本時間。
4. `docs/ideas/README.md` の「現行アイデア一覧」に行を足す。

## ステータス変更
- フロントマターの `ステータス` と `更新日` を変え、判断ログに「日付・判断・理由」を1行足す。一覧表も更新する。
- `保留` は再検討の条件、`却下` は理由を必ず書く。ファイルは消さない。
- `検証中 → 実装中` に進めるときは `start-project` スキルを使う。

## 報告
登録/更新した ID・タイトル・ステータスと、暫定で置いた値を返す。検証すべき仮説があれば `add-todo` での todo 化を提案する。
