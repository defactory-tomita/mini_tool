# アイデア棚卸し

ステータスの定義は `docs/ideas/README.md` が正。SES_sales の `knowledge-review` スキルと同じく「提案 → 承認 → 反映」の2段階で進める。

## 1. 棚卸し（読み取りのみ）
- `docs/ideas/IDEA-*.md` のフロントマターを一覧化し、次の観点で表にして報告する:
  - インパクト高 × 手間小 のもの（最優先候補）。
  - 同じステータスに長く留まっているもの（`更新日` が古い）と、その原因（次の一手が書かれていない、todo が止まっている等）。
  - 紐づく `docs/todo/` の status。完了した検証 todo の結果がアイデア側に反映されているか。
  - テーマが重複・統合できそうなもの。
  - `docs/knowledge/insight/` のうち、まだアイデア化されていないが打ち手が見えているもの。
- 提案は「次に進める（どのステータスへ・次の一手）」「保留/却下候補（理由）」「統合候補」「据え置き」に分類する。**この段階ではファイルを変更しない**。富田の判断を待つ。

## 2. 反映（承認されたもののみ）
1. 各アイデアのステータス・`更新日`・判断ログを更新する（`new-idea` スキルの「ステータス変更」と同じ）。
2. 統合する場合は、残す側に内容と出所を寄せ、もう一方は `ステータス: 却下`、判断ログに「IDEA-XXXX に統合」と書く。
3. `docs/ideas/README.md` の一覧表を更新する。
4. 次の一手を todo にする場合は `add-todo` スキルで登録する。
