# dev-log 引き継ぎメモ

運用の正は `docs/dev-log/README.md`。

## どこに書くか
- 既存メモと**同じテーマの続き**（同じ SPEC・同じプロジェクト）なら、そのファイル末尾の `## 追記履歴` 表（`| 日付 | 内容 | 担当 |`）に行を足す。表が無ければ新設する。
- 新しいテーマなら新規ファイル: `docs/dev-log/<関連doc_id>_<YYYY-MM-DD>_<内容の要約>.md`。doc_id は `SPEC-XXX`、仕様書が無ければ `IDEA-XXXX`。

## 新規ファイルの構成
1. `## 背景` — 何が問題で、富田からの指示は何だったか（要約・番号付き）。
2. `## 設計・実装` — 決定事項と**なぜそうしたか**。触ったファイル・関数名を具体的に。富田が手で行う作業（APIキー登録など）は明記。
3. `## 既知の制約・バグと対処`
4. `## 残タスク` — 次のセッションがそのまま着手できる粒度で。

## 書いた後
- このセッションの変更をもとに書く（`git log` / `git diff` で事実を確認し、推測で書かない）。
- 仕様として確定した内容は `docs/spec/` 側にも反映が必要か確認し、必要ならユーザーに提案する。
- 実行タスクとして切り出すべき残タスクは `add-todo` スキルで登録を提案する。
