# docs ― 全体マップ

> `docs/` は「アイデアを実装まで運ぶパイプライン」と、それを支える「ナレッジ層」「サポート層」で構成する。新しい情報を書くときは、まずどの層に属するかを判断する。

---

## ① アイデア・パイプライン ― 着想から実装・運用まで

```
docs/ideas/      アイデア（IDEA-XXXX）  ―「何を作る／何をやるか」の一次受け皿
      │  着想 → 検討中 → 検証中 ──（作ると決めた）──┐
      │                                         ▼
docs/spec/       仕様（SPEC-XXX）       ―「何をどこまで作るか」（実装の正）
      │
      ▼
projects/<名前>/ 実装                   ―  実体（コード・テスト・README）
      │
      └─（運用・振り返り）→ アイデアのステータスを「運用中」へ、学びは knowledge/ へ
```

| フォルダ | 一言 | 詳細 |
| :--- | :--- | :--- |
| [`ideas/`](ideas/README.md) | 事業アイデア・開発アイデアの一次受け皿 | [ideas/README.md](ideas/README.md) |
| [`spec/`](spec/README.md) | 実装すると決めたものの仕様書 | [spec/README.md](spec/README.md) |
| [`../projects/`](../projects/README.md) | 実装本体（1プロジェクト＝1ディレクトリ） | [projects/README.md](../projects/README.md) |

アイデアは**捨てずに残す**。「却下」「保留」もステータスとして記録し、なぜそう判断したかを各ファイルの判断ログに書く（後で状況が変わったときに再評価できるようにするため）。

---

## ② ナレッジ層 ― アイデアの根拠

| フォルダ | 位置づけ |
| :--- | :--- |
| [`knowledge/fact/`](knowledge/README.md) | 観測された客観事実（市場・競合・技術・顧客の状態など） |
| [`knowledge/insight/`](knowledge/README.md) | 事実から導いた解釈・仮説・気づき。しばしばアイデアや検証 todo を生む |

---

## ③ サポート層

| フォルダ | 位置づけ | 詳細 |
| :--- | :--- | :--- |
| [`dev-log/`](dev-log/README.md) | AIセッションをまたぐ実装引き継ぎメモ | [dev-log/README.md](dev-log/README.md) |
| [`todo/`](todo/README.md) | 検証・実行タスク | [todo/README.md](todo/README.md) |

`docs/` の外側では、`projects/`＝実装実体、`config/`＝設定・認証情報テンプレート、ルート直下の `変更履歴.md`＝構造変更ログ、が対になる。

---

## 新しい情報が来たら、どこに書く？

```
その情報は…

├─ 「こういう事業／ツールがあったら」という思いつき・構想？
│    → ideas/ に書く（IDEA-XXXX。粗くてよい。既存アイデアと同テーマなら追記）
│
├─ 市場・競合・技術・顧客について観測した事実？
│    → knowledge/fact/ に書く
│
├─ その事実から導いた仮説・気づき（まだアイデアの形になっていない）？
│    → knowledge/insight/ に書く（根拠の fact と相互参照）
│
├─ 実装すると決めたアイデアの要件（何をどこまで作るか）？
│    → spec/ に書く（frontmatter でバージョン管理）。アイデア側の spec 欄にリンク
│
├─ 実装コードそのもの？
│    → projects/<名前>/ に置く
│
├─ 複数AIセッションをまたぐ実装の引き継ぎ（決定事項・バグと対処・残タスク）？
│    → dev-log/ に書く（仕様として確定したら spec/ 側へ反映）
│
└─ 誰が・いつ・何をやるかの検証/実行タスク？
     → todo/ に書く
```

SES営業そのものに関する知見・戦略・自動化は `defactory-tomita/SES_sales` に書く。

**共通ルール:** ドキュメント・ディレクトリ構造**自体**を変更したら、背景込みでルート直下の `変更履歴.md` に記録する（新しい記録を上に追記）。
