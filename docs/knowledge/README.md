# docs/knowledge ― ナレッジ層（アイデアの根拠）

> **位置づけ:** アイデアの根拠になる「事実」と、そこから導いた「気づき」を蓄積する。
> 気づき（insight）が具体的な打ち手の形になったら `docs/ideas/` にアイデアとして登録する。SES_sales の `docs/knowledge/` と同じスキーマ。

---

## ナレッジの2種類
| 種別 | フォルダ | 内容 | 性質 |
| :--- | :--- | :--- | :--- |
| **ファクト** | `fact/` | 観測された事実（市場・競合・技術・顧客の状態など） | 客観。確度を付して蓄積 |
| **インサイト** | `insight/` | 事実から導いた仮説・気づき | 主観・解釈。**アイデアや検証todoが派生する** |

- 仮説の根拠となった事実は `fact/` に置き、`insight/` から相互参照する（事実と解釈の分離）。
- SES営業に関する知見は SES_sales 側に書き、こちらからはパスで参照する（二重管理しない）。

## メタ情報スキーマ（各ファイル冒頭のフロントマター）
| 項目 | 値の例 | 意味 |
| :--- | :--- | :--- |
| `title` | 中小企業のAI導入は実演が決め手 | 知見のタイトル |
| `種別` | fact / insight | ファクトか気づきか |
| `重み` | 高 / 中 / 低 | アイデア・事業判断への影響度 |
| `確度` | 確定 / 検証中 / 観測ベース（要検証） | 事実としての確からしさ |
| `ステータス` | 観測 / 検証中 / アイデア化済み | 進捗 |
| `関連` | fact/xxx.md, ideas/IDEA-0001_xxx.md | 相互参照 |
| `登録日` / `更新日` | 2026-10-06 | 日本時間の日付 |

本文は `出所:` 行（会議名・日付・URL） → `## 観測された事実` → `## 含意（一般化）` の順に書く。

## ファイル命名
- 1知見＝1ファイル。`fact/<トピック>.md` / `insight/<トピック>.md`。同じテーマがあれば新規作成せず追記する。
