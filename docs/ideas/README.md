# docs/ideas ― 事業アイデア・開発アイデア（一次受け皿）

> **位置づけ:** 思いついた事業アイデア・開発アイデアを、粗い段階からすべてここに記録する。
> 1アイデア＝1ファイル。ステータスで「着想 → 検討 → 検証 → 実装 → 運用」の進捗を管理し、作ると決めたものだけを `docs/spec/`・`projects/` へ進める。

---

## アイデアの2種類
| 種別 | 内容 | 例 |
| :--- | :--- | :--- |
| **事業** | 収益を生む新規事業・サービス・商材 | 新サービス、既存事業の横展開、提携モデル |
| **開発** | 社内外で使うツール・自動化 | 業務の自動化、社内向けミニツール、検証用プロトタイプ |

事業アイデアの検証のために開発アイデアが派生することもある。その場合は `関連` で相互参照する。

---

## ステータスの流れ
```
着想 ──→ 検討中 ──→ 検証中 ──→ 実装中 ──→ 運用中
  │        │          │          │
  └────────┴──────────┴──────────┴──→ 保留 / 却下（理由を判断ログに残す）
```
| ステータス | 意味 | 次に進む条件 |
| :--- | :--- | :--- |
| 着想 | 思いついた段階。一言と背景だけでよい | 誰の何の課題かが言える |
| 検討中 | 課題・解決策・検証したい仮説を書き出している | 検証方法（誰に聞く／何を作る）が決まる |
| 検証中 | ヒアリング・試作・数字の裏取りをしている（todo が紐づく） | 「作る」と判断した → spec を作成 |
| 実装中 | `docs/spec/` と `projects/` が存在し、作っている | 使い始めた |
| 運用中 | 実際に使われている／事業として回っている | ― |
| 保留 | 今はやらないが、条件が変われば再検討する | 判断ログに「再検討の条件」を書く |
| 却下 | やらないと決めた | 判断ログに理由を書く（ファイルは消さない） |

## メタ情報スキーマ（各ファイル冒頭のフロントマター）
| 項目 | 値の例 | 意味 |
| :--- | :--- | :--- |
| `id` | IDEA-0001 | 一意なID（4桁連番） |
| `title` | 議事録から自動でナレッジを抽出するツール | アイデアのタイトル |
| `種別` | 事業 / 開発 | 上表 |
| `ステータス` | 着想 / 検討中 / 検証中 / 実装中 / 運用中 / 保留 / 却下 | 上表 |
| `インパクト` | 高 / 中 / 低 | 当たったときの効果（売上・工数削減など） |
| `手間` | 大 / 中 / 小 | 形にするまでの工数・コストの見積もり |
| `出所` | 2026-10-06 定例mtg / SES_sales:docs/knowledge/insight/xxx.md | どこから生まれたか |
| `関連` | ideas/IDEA-0002_xxx.md, knowledge/insight/yyy.md | 相互参照 |
| `spec` | docs/spec/xxx_spec.md | 実装中以降に記入 |
| `project` | projects/xxx/ | 実装中以降に記入 |
| `登録日` / `更新日` | 2026-10-06 | 日本時間の日付 |

本文の構成は [`_template.md`](_template.md) に揃える。

## ファイル命名
- `docs/ideas/IDEA-XXXX_<タイトルの要約>.md`（例: `IDEA-0001_議事録ナレッジ抽出ツール.md`）
- ID は `origin/main` 上の最大番号 +1（他ブランチと衝突したら、後からマージする側でリネームする）。
